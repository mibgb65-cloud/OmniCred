# 应用内更新

Windows 正式安装版的设置页支持：检查稳定版本 → 下载更新 → 校验完成提示 → 用户点击“重启并更新” → Windows 授权 → 应用退出 → 静默覆盖安装 → 以原用户身份重新打开。

下载期间可继续使用其他页面，也可取消下载。下载失败、大小不符和 SHA-256 校验失败都不会开放安装入口；失败文件会清理，用户可重新下载。点击重启时会再次校验。退出应用会取消尚未完成的下载；已准备但未安装的包也会清理，下次需重新下载。当前没有断点续传。

## 支持范围

- 仅 Windows 正式安装版启用；开发版、便携版和其他系统保留发布页安装入口。
- 使用 Windows 原生系统架构匹配安装器；发布流程当前构建 amd64。如果未来发布 arm64，须同时构建相应安装器。
- 旧版客户端首次迁移需要手动安装包含此功能的版本，后续版本必须携带兼容清单。
- 当前安装器使用管理员权限；系统可能显示一次 UAC 授权提示。取消授权时应用保留运行，安装包保持可重试状态。静默参数不会绕过系统授权，参见 [Microsoft ShellExecuteEx 说明](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfow)。
- 更新前应保存未提交的表单；安装器保留数据库、配置和数据位置。旧程序退出前不修改应用文件；替换失败会尝试恢复旧 EXE。断电或强制结束安装器不属于自动回滚保证范围。

## 模块与安全边界

`internal/updater` 负责稳定版检查、清单解析、下载和状态管理。版本信息仍通过只读 `GET /api/v1/settings/updates` 返回。下载、取消、读取下载状态和重启安装通过 Wails `desktop.App` 绑定调用，HTTP API 不接受下载地址、文件路径或安装指令。

仅从固定 GitHub 仓库获取清单和安装器，只接受 HTTPS，限制重定向到 GitHub 的附件域名。版本格式、协议、架构、文件名、大小和摘要必须匹配；元数据限制为 1 MiB、清单 64 KiB、安装器 512 MiB，检查超时 12 秒、下载超时 30 分钟。网络错误不展示可能包含临时签名的附件 URL。

SHA-256 校验保证文件与通过 GitHub HTTPS 获取的清单一致；它不是独立的发布者数字签名。此设计信任仓库及发布工作流，尚未引入独立签名密钥或代码签名基础设施。

缓存位于 `%LOCALAPPDATA%\OmniCred\updates\download-*`。临时文件完成下载和校验后才重命名为 `installer.exe`。安装时，主程序与辅助进程通过 Windows 只读共享句柄锁住安装包，防止校验与执行之间文件被替换或改写。下一次下载会清理超过 24 小时的旧缓存目录。

`internal/desktop` 将当前 EXE 复制为缓存中的更新辅助进程，避免辅助进程本身锁住待覆盖的主程序。辅助进程校验包后通过 `ShellExecuteExW` 请求 UAC，取得安装器进程句柄，再通知主程序退出。安装器使用 `/S /UPDATEPID=<pid> /D=<当前安装目录>`，等待旧进程退出，保留旧 EXE 作为临时备份，成功后清理备份；失败时尝试恢复。辅助进程等待安装器完成，再用原有用户权限和启动参数重启主程序。启动失败和安装失败会显示明确提示。

`/D` 必须位于参数末尾，含空格时也不能用引号包裹，参见 [NSIS 命令行说明](https://nsis.sourceforge.io/Docs/Chapter3.html)。更新模式保留调用方传入的目录，避免注册表中的其他安装位置覆盖它。

安装入口 `build/windows/installer/project.nsi` 通过 `/CHARSET=UTF8` 加载 `project.nsh`，使中文文案在不同 Windows 系统编码下均可正确构建，同时保持源码为 UTF-8 无 BOM。

## 验证

```powershell
go test ./...
go run ./tools/linecheck
Push-Location frontend
npm test
npm run build
Pop-Location
./tools/check-update-installer.ps1
```

安装器验证脚本只操作工作区 `.cache` 中的测试目录，不修改注册表和正式安装。它实际运行共享 `update.nsh` 逻辑，检查等待原进程退出、中文空格路径、成功替换、失败回滚、数据保留与非法参数拒绝。发布工作流也执行此验证。

真实发布验收还需在 Windows 测试机中完成一次已安装旧版到新版的升级，覆盖 UAC 允许/取消、磁盘不足、进程被占用及管理员使用另一账号授权的情况。自动化测试不会在开发电脑上执行正式安装器。
